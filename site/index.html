A cancelled upload still published its bytes.

FileBackend.uploadObject accepted an AbortSignal but never passed it to the pipeline that copies the request body to disk. A cancelled call could keep reading, publish the file and report success. This lab reproduces that on real files, proposes a small fix upstream, and is explicit about what the evidence does not prove.

Why it exists

An HTTP success is not proof that the right bytes are on disk.

Without it

A client gives up on an upload, the server-side adapter keeps streaming anyway, renames the staging file into place and reports success. If an object already existed at that destination, the transfer the client had abandoned replaces it anyway.

With it

Pre-aborted calls are rejected before staging, an abort mid-transfer stops the pipeline, the old object is preserved and the staging file is removed. Five focused regression tests pin the behaviour.
