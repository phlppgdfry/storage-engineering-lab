# Bounded cycle and evaluation decision (before execution)

Problem: select and run one reproducible, auditable local experiment without an unrestricted command-generating agent. Context: H001 is already submitted; publication must not wait for automation. Alternatives: LLM/multi-agent framework, database service, property/mutation framework, deterministic Node scripts. Decision: reuse Node test/process/stream primitives and existing owned-run/timeout/evidence helpers, JSONL memory and three hand-written safe stream mutations. No new dependency or model/API access is needed. Property-based shrinking adds little for three explicit mutants; mature upstream Vitest remains the oracle for real storage findings.

A cycle selects one eligible probe from the fixed experiment catalog, executes a correct control plus a selected safe mutation twice, performs a deterministic skeptical review, and appends hashed evidence and a hash-chained memory entry. Impact/coverage and cost are fixed catalog fields; adaptive scores add observed verified yield and penalize failed attempts. It can alter selection, never commands, corpus, labels or acceptance rules. One iteration only, 5-second process deadline, 1 MiB fixture payload, 16 MiB output cap inherited from the runner, owned temp cleanup, no automatic retries. No external writes. This is a research prototype, not an AI model, semantic reviewer, security sandbox or production storage simulator.

Evaluation corpus is frozen in `corpus.json` before execution. Training cases are isolated from the eight held-out cases. Mutation mechanisms intentionally recur, so this is a small conformance exercise, not independent real-world generalization. Fixed order, adaptive training-only rank and seeded random order each receive two probes per case; every probe runs twice and controls must pass. All actual matrix results are retained. Stop on the fixed corpus; do not tune it to make adaptive win. Record defect recall, experiments/detection index, reliability, false positives, evidence completeness and observed runtime. Wall time is descriptive on this host. The predeclared decision is in the corpus. No performance or learning claim follows from merely persisting memory.

Risks: allowlists constrain input-to-command translation but trusted local scripts and Node are outside that boundary. No OS CPU/memory/network containment is promised. Locks fail closed after a crash; no stale-lock auto-deletion. A crash can leave RUNNING evidence unindexed; retain it and reconcile manually. Atomic exclusive record creation and hash verification detect torn/corrupted history, not malicious rewriting of all history by a user with filesystem access. Review is deterministic consistency checking, not independent scientific confirmation. Human review and current upstream-overlap checking remain necessary before a real finding is published.

Optional Storage Doctor integration remains a future versioned sanitized JSON input contract: hypothesis suggestions only, no executable commands, secrets, arbitrary paths or automatic CONFIRMED status. No bundle was available to validate a useful adapter; no Doctor code, coupling or duplicate diagnostics are added.
