## Reviewed safeguards and their practical limits

- `fixtureEnv` uses an allowlist of process essentials and tracked samples, strips ambient credentials/proxies/Node import hooks, disables telemetry and metadata lookup, and disables global/system Git configuration and hooks for host Git commands. Exact synthetic endpoint checks run before container test/migration code. Independent tests reject every missing endpoint and a non-fixture value for every endpoint key. Direct unmanaged invocation of `assertDisposable` rejects before source/service access on this host.
- `prepareSource` creates a detached worktree at the fixed commit and records tracked regular-file hashes. Container execution checks lockfile/adapter identity, verifies every listed source file and reconstructs the expected Git tree in a temporary bare index. This is materially stronger than a hardcoded Docker label or adapter hash alone. The pinned build path excludes private `.env*` with sample exceptions; dependency lifecycle scripts run in the separate network-disabled rebuild step. Apt packages are not snapshot-pinned and installed dependency bytes are not universally authenticated; documentation correctly bounds those claims.
- The Compose recipe removes fixed container names/published ports, uses a unique project plus ownership labels, isolates the default runtime network and rejects external volumes. Teardown checks labels on project containers/networks/volumes before `down --volumes --remove-orphans`; image cleanup checks its owner label. Host temporary cleanup checks a regular ownership marker and rejects substituted symlinks/tokens. These are intended guards against mistakes, not isolation against a hostile local administrator or race-capable process modifying the Docker daemon/filesystem.
- The final preflight now checks all three resource kinds — containers, networks and volumes — before creating the source/build/services. This resolves the earlier code-review observation that freshness was checked only for containers. The fake-CLI tests independently exercise container collision refusal and endpoint precedence; this reviewer did not execute a real daemon collision experiment or separately inject network/volume collisions. Their guards are confirmed by source inspection, not misrepresented as an independently executed Docker fault matrix.
- `runCommand` uses argument arrays without a shell, bounded output, per-channel line buffering/redaction, explicit allowed exit codes, timeouts/abort handling, process-group termination with a retained SIGKILL deadline, exclusive evidence files and listener cleanup. Existing tests exercise source/environment isolation, marker substitutions, output chunk redaction, nonzero/spawn failures and a TERM-resistant descendant. The newly corrected callback write-error handling was independently fault-injected: an ENOSPC from `writeSync` rejects under control and terminates the child instead of escaping as an uncaught callback exception.
- The final runtime wrappers preserve source restoration attempts in `finally`, mark cleanup failures as failures, and retain evidence rather than unconditionally reporting success. Build cache or resources intentionally retained after a failed ownership check are not evidence of deletion of another project's resources. No general secret-scanning or complete sandbox guarantee is warranted; the redactor is explicitly best effort.
- Native probe imports now sit inside the cleanup `try`, and backend close cannot prevent the nested `finally` from removing probe data. A separate synthetic import-failure test in `test/container.test.mjs` passed: source configuration deliberately throws, the command fails, its probe directory is gone, and a sentinel outside that directory is intact. This uses Node 24 native type stripping, not tsx or production dependencies; the real-tsx path is covered separately by the inspected successful export artifact. No claim is made that standalone probes survive SIGKILL; the managed host wrapper owns the enclosing child TMPDIR and removes it after process-group shutdown.
