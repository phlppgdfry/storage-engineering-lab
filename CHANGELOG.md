# Changelog

## 1.0.0 — portfolio edition

This is a versioned research artifact, not a production Storage distribution, hosted service or npm package. The [official release record](https://github.com/phlppgdfry/storage-engineering-lab/releases/tag/v1.0.0) records publication status, exact commit, release PR and hosted validation. This changelog describes the edition; release completion requires those operations to succeed.

### Included

- Native upload cancellation reproduction, five upstream regression/control cases, a focused proposed fix and an actual terminal demonstration. [Case study](reports/file-upload-cancellation.md).
- Pinned source/dependency checks, owned temporary workspaces, bounded process execution and scoped Linux/PostgreSQL verification with retained raw evidence.
- A separate file-GET cancellation correction, nineteen regression cases and real local HTTP disconnect experiments; a separately reviewable lifecycle configuration test-fixture correction. [Engineering audit](reports/advanced-engineering.md).
- Experimental, one-iteration research tooling with append-only evidence references, deterministic controls and failure handling. Final-component symlink replacement protection was strengthened; trusted parent directories remain an explicit assumption.
- A compact architecture explanation, reproduction instructions and factual interview walkthrough.

### Evidence and limitations

- Preserve all 130 historical measurement groups, failed runs and unfavorable results. Normal-upload performance remains INCONCLUSIVE; no throughput, universal cleanup or production-impact claim.
- The frozen planner evaluation is NONDISCRIMINATING. Fixed selection remains default; self-improvement is not demonstrated.
- The standalone lab has no npm dependencies. Pinned upstream fixtures contain known advisories and require disposable, synthetic-only use. No production security certification is implied.
- Upload PR [#1616](https://github.com/supabase/storage/pull/1616) remains draft and unmerged. Download and lifecycle corrections are archived as separate contributions, not submitted upstream; no upstream endorsement is claimed.
- Current test counts, platforms, retained failures and unexecuted gates are in the [closure report](reports/final-project-closure.md). Earlier Linux/PostgreSQL results are not silently reassigned to newer revisions.

The Apache-2.0 license and upstream attribution are unchanged. `package.json` records `1.0.0` for release consistency and remains `private: true`.
